# Skill迭代一致性检查清单

> **背景**：publishing SKILL.md经历5+次迭代，多次出现"改了A处忘了B处"的bug。
> 以下检查清单用于每次迭代后自检，避免累积不一致。

## 检查项

### 1. 标记一致性
- [ ] 步骤5b的 ❌/⚠️/✅ 标记是否与"三道硬门"一致？
  - ❌ = 强制缺（必须补）
  - ⚠️ = 优先缺（建议补，非强制）
  - ✅ = 已有
- **已知陷阱**：身份词用 ❌ 但硬门说"非强制" → 应统一用 ⚠️

### 2. 数据源完整性
- [ ] 步骤2读取了 `how`/`why`/`what` 三层吗？
- [ ] 封面步骤读取了distill的封面数据吗？（`thumbnail_guidelines`/`cover_title_synergy`/`why.thumbnail`）
- [ ] 读取时序表是否覆盖了所有数据源？

### 3. 评分标准 vs 硬门
- [ ] 评分标准里的"有/无"描述是否与硬门的"强制/优先"一致？
- **已知陷阱**：评分90-100说"有高位身份词"但硬门说"非强制" → 应改为"优先有"

### 4. 输出格式完整性
- [ ] 输出JSON是否包含所有生成的中间产物？
  - `template_card` — 选了哪张模板卡
  - `reference_prompts` — 注入了哪些参考prompt
  - `generated_prompt` — 实际生成的完整生图prompt
- [ ] 字段名是否与步骤描述一致？（如同构骨架 vs skeleton）

### 5. 拼写和格式
- [ ] 标签层是否有拼写错误？（如 beggging → begging）
- [ ] 引用的文件路径是否正确？
- [ ] 引用的数据字段名是否与distill.json实际结构一致？

## 已知Bug历史

| Bug | 原因 | 修复 |
|-----|------|------|
| 身份词 ❌ vs 硬门非强制 | 改了硬门忘了改5b标记 | ❌→⚠️ |
| 缺what层 | 步骤2只读how/why | 补充what引用 |
| 封面缺distill数据 | 封面步骤只引用references文件 | 补充distill字段引用 |
| 输出格式缺封面详情 | 迭代时没更新输出JSON | 补充template_card等字段 |
| beggging拼写 | 原始输入错误 | → begging |
| 评分90-100"有"vs"优先有" | 改了硬门忘了改评分标准 | → 优先有 |

## 使用方法

每次修改SKILL.md后：
1. 逐项检查以上清单
2. 修复发现的不一致
3. 提交git
4. 更新此文件的Bug历史表
